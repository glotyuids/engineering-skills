# ADR-0000: A full sentence stating the decision

Status: Proposed
Date: YYYY-MM-DD

## Context

What forced a decision. Include the alternatives considered and why they were live
options — an ADR whose context does not explain the tension is not worth writing.

## Decision

Imperative and specific. Say what will be done, not what was discussed.

## Consequences

Bulleted, and honest about the downsides. List what becomes harder as well as what
becomes possible, and anything this decision commits the project to.

---

Conventions for this directory:

- File name `NNNN-kebab-title.md`, four digits, never renumbered.
- The title is a **sentence stating the decision**, not a topic noun.
- Status is one of Proposed / Accepted / Superseded by ADR-NNNN.
- ADRs are **amended with dated notes, never rewritten**. If the decision changes, write a
  new ADR and mark this one superseded.
- Status markers used in project docs: ⏳ planned · 🚧 flag-gated · 🧟 legacy · ❌ dropped.
